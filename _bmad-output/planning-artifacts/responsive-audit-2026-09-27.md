# Responsive audit — creatives.exchange — 2026-09-27

Scope: phone widths (375/390/430) weighted heaviest per Rick's priority call, with the mobile bottom nav given its own section; tablet (768×1024, 1024×768) and desktop (1440×900) got a lighter pass. Audited against the dev Convex backend (`giant-wildebeest-814`), signed out throughout (the app-shell routes `/today`, `/search`, `/projects`, `/events` were temporarily made public via `PUBLIC_PATH_PREFIXES` in `_app.tsx` to reach them without signing in, then reverted — verified clean, see bottom). No horizontal scroll/overflow was measured on any route at any of the six viewports — the bones of the responsive grid hold up. The real problems are all inside the phone chrome: the mobile bottom nav's tap targets sit under Apple's 44×44 guideline everywhere, it carries no `env(safe-area-inset-bottom)` so it will crowd the home-indicator gesture strip on notched iPhones, and it drops several destinations the desktop rail keeps (the Garden/Exchange switcher, About, Invite) with **no substitute path** to them from inside the app shell on a phone. Two further layout breaks: the "+ Post a project" dropdown renders off the left edge of the screen on every phone width, and the shared `FilterButton` component has no visible label on mobile (`hidden sm:inline`) and no `aria-label`, so it's an unlabeled icon everywhere it's used (`/search`, `/projects`, `/events`).

## Mobile bottom nav — dedicated section (Rick's priority)

**Destinations, signed-in vs signed-out, vs the desktop rail**

| | Desktop rail (`aside`, `md:flex`) | Mobile bottom nav (`nav.fixed.bottom-0`, `md:hidden`) |
|---|---|---|
| Signed out, public page | People, Projects→`/opportunities`, Events→`/garden/events` (Spaces/Learn are code-complete but hidden behind `FF_V2=false`, so absent from both) | Same 3 items — **verified [Certain]**, screenshots `communities__375x812.png` etc. |
| Signed in | Today, People, Projects, Events, Following, Profile, **+ Invite someone, + Garden/Exchange switcher, + other communities row, + admin Crawler/Waitlist (if admin), + "About creatives.exchange →"** | Today, People, Projects, Events, Following, Profile, **+ Messages icon appended separately in JSX** — 7 icons total. **[Certain] from reading `_app.tsx` lines 161–282**; not directly screenshot-verified because the audit stayed signed out per instructions. |

So on a phone, once past the primary five, a signed-in member has **no way to reach**: `/communities` (the Garden/Exchange switcher — desktop-only, `hidden md:flex`, not gated by `FF_V2`), `/about/index.html` (only link is the rail's footer row), or "Invite someone" (`InviteCTA`, rail-only). These three exist solely in the `<aside>` block (`app/app/routes/_app.tsx:284-488`), which is `hidden` below the `md` breakpoint with no mobile equivalent (no hamburger menu, no "more" tab). `/join` isn't linked from either nav (it's reached via page-level CTAs, not chrome) — that's the same on both, not a phone-specific gap. Settings/Profile and Messages **are** reachable on phone (`/settings` via the "Profile" icon, `/messages` via the appended Messages icon) — those are fine.

**Icon-only items — accessible name and clarity**

Every bottom-nav link does get an `aria-label` (`aria-label={item.label}`, `_app.tsx:245`) and the appended Messages link is labeled too (`:269`) — screen-reader users get real names. **[Certain]**, confirmed via `page.evaluate` reading `getAttribute("aria-label")` (see `bottomNav.items` in the raw results). What's missing is a *visible* label — every item is icon-only with no text, so a sighted first-time user has to infer "briefcase = Projects" and "calendar = Events" cold. **[Likely] Minor–Major**, contrasts with the desktop rail which pairs every icon with a text label.

Active state: code sets `color: var(--app-accent-ink)` for the active item vs `var(--app-text-dim)` otherwise (`_app.tsx:244`). I could not screenshot this directly (none of the routes I could reach signed-out matched `location.pathname.startsWith(item.path)` for a bottom-nav item — e.g. on `/communities` none of People/Projects/Events is "active"). **[Likely]** the mechanism works since the identical pattern is used and screenshot-verified on the desktop rail (`today__768x1024.png` shows "Projects" lit green when active), but the phone case itself is untested here.

**Content coverage / overlap**

- `<main>` carries `pb-20 md:pb-0` (80px on phone) against a measured nav height of **65px** — 15px of slack, so page content does clear the bar. **[Certain]**, measured on `/communities`, `/today`, `/projects`, `/events` @ 390×844 (`bottomNav.mainPaddingBottom: "80px"`, `bottomNav.navHeight: 65`).
- No overlap with the showcase ticket modal (`showcase_ticket__390x844.png` — modal sits well above the bar with margin) or the Creator Notes expansion on `/today` (`today_creatornotes__390x844.png` — content scrolls past the bar cleanly, bar stays on top with its own z-index/shadow).
- The Filter panel (`/projects`, opened) does **not** overlap the bar either (`filter_projects_manual__390x844.png`) — the 28-pill grid stays well clear.
- The "+ Post a project" menu is a separate, real bug (see Findings table) but it's a horizontal clipping issue, not a bottom-nav overlap.
- **No `env(safe-area-inset-bottom)` anywhere in the codebase** — `grep -rn "safe-area" app/` returns zero hits. **[Certain]**. The fixed nav's own bottom padding (`py-3` = 12px top+bottom, applied to the flex row, not the safe area) doesn't reserve room for the iPhone home-indicator gesture strip. Headless Chromium can't render the actual notch/indicator overlay, so the *visual* crowding is **[Likely]** rather than screenshot-proven, but the missing CSS mechanism is certain — on a real iPhone (14/15/16 series) the 65px-tall bar's icon row will sit flush against the gesture area with no breathing room, and Apple's own guidance is to pad for it.

**Tap target size and spacing at 375px**

Every bottom-nav item measures **40×40px** (`w-6 h-6` icon = 24px + `p-2` padding = 8px each side), signed-out (3 items) and by the same math signed-in (up to 7 items — Today/People/Projects/Events/Following/Profile/Messages). That's under the 44×44 minimum on **both dimensions**, on **every route tested**, at all three phone widths. **[Certain]**, directly measured (`getBoundingClientRect()`), consistent across `375x812`/`390x844`/`430x932`. At 375px width, 3 items of 40px fit with room to spare (`flex justify-around py-3` distributes the remaining ~250px as gaps); a signed-in 7-item bar would still fit width-wise (7×40=280 < 375) but the touch targets themselves don't grow — the shortfall is height/width of each target, not overall bar width.

**Top-of-screen identity ("where am I")**

The desktop rail shows a persistent "THE GARDEN / SAN DIEGO · ONLINE" label at the top of every app-shell page (`_app.tsx:294-306`, confirmed on `/today`, `/projects`, `/events`, `/communities` @ 768×1024). On phone there is **no equivalent persistent header** — the `<aside>` that carries it is `hidden` below `md`, and `<main>` renders the routed page directly with no wrapper chrome. `/today` happens to render its own local "TODAY IN THE GARDEN / SUN, SEP 27" heading (`today_creatornotes__390x844.png`), but `/projects`, `/events`, and `/search` open straight into their own page title ("Projects", "Events") with no "Garden" branding or location context at all (`projects__390x844.png`, `events__390x844.png`). **[Certain]** — screenshot-verified absence on 3 of 4 primary routes, present-by-accident on the 4th.

## Works well

- Zero horizontal overflow anywhere — 6 viewports × 15+ routes, `document.documentElement.scrollWidth` never exceeded `innerWidth`.
- The fixed bottom nav never covers page content or a modal on the routes and overlays actually opened (Filter panel, showcase ticket modal, Today's Creator Notes) — `pb-20` gives a clean 15px of clearance over the bar's real 65px height.
- The `md:` breakpoint transition at exactly 768px is clean — rail appears, bottom nav disappears, no double-chrome or gap.
- Bottom-nav and rail items all carry proper `aria-label`s even where visible text is absent.
- The showcase ticket modal is well-built for phones: centered, comfortably inset from all edges, no overflow, no clipping.
- Desktop/tablet grids (project cards, tag pills) collapse to single-column cleanly on phone with no distorted images.
