What this shows. The operator report as a real table: the spec's "What we measure" columns plus the two the report already carries (still open, directed $), one row per month, newest first, numbers right-aligned in tabular figures. Opened, distinct recipients and plus-up rate are set in paper so the three numbers that answer "is it spreading, are they adding" read first. Totals sit above as cells. The per-member list follows (getGivingReport.members): months directed in a row, months directed of months opened, plus-up count, last period, total plussed up; sorted largest plus-up total first, then streak. Directed amounts also appear on the community's pool card above as member_gift_out rows (negative pool cents).
  • Numbers are sample values for layout only; the feature is not live.
  • Under 980px the table scrolls sideways inside its section with the month column pinned; it is the one horizontal-scroll element in the product.
  • PostHog gets only the funnel events (giving_notice_opened, giving_decided, giving_plus_up_started) with target type; never an amount or a name.
